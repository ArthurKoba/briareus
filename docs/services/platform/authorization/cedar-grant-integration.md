# Authorization: Cedar on current AgentSession grants

This slice changes the **source-only owner operation paths** `AccessSourceService.verify_current_grant` and `AccessOwnerProofReader.issue_live_agent_session_grant`. It does not activate a previously unmounted business HTTP endpoint or prove current production/Development MCP enforcement.

`_access_cedar.py` binds the existing **authoritative** Authorization `sessions.agent_sessions` row to the compiled Rust-backed Cedar evaluator. A positive decision requires a verified actor, matching Project, active/unrevoked session, exact current revision, nonexpired grant, listed action and Cedar policy permit. The code-owned initial policy allows only `files.read` / `project.metadata.read` in a normal session; other known rights require `is_elevated`, as issued by owner approval. Unknown actions fail closed. Neither the unsigned session UUID nor a JWT alone grants access. A revoke increments the row revision and changes its active status; a later fresh check denies.

This is a **baseline** policy, not yet a policy management API. Configurable per-Hand/per-tool rules, Rauthy subject projection, reliable approval/revoke transport and policy-version fence/invalidation at active Hand boundaries still need owner-verified interfaces. The current signed-owner source contract remains mandatory until equivalent OAuth/resource enforcement is live. Runtime may not treat this source slice as a ready authorization endpoint. Continue using the same single approved PostgreSQL server and Authorization owner database; no new database, schema, or Valkey dependency was introduced.
