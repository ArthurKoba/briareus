## Common guarded contract

The four new metadata tools share one [staged factory](../../shared/hand_runtime/_owner_metadata.py) and the [Hand per-tool PEP](../../shared/hand_runtime/_effect_auth.py). A trusted supervisor, not MCP JSON or ENV, must inject (1) an owner resolver returning canonical executable arguments, (2) independently authenticated private Cedar decision transport and (3) current resource-owner inspector. The inspector must independently check the original signed actor, Project/AgentSession, current lease, exact resolved resource and grant on every operation,\nincluding a final source-scope check after awaited owner inspection. It can return only the bounded DTO with state = active/inactive/degraded/unknown and positive revision; arbitrary provider JSON, paths, account IDs, cookies and secrets are not exposed. Missing signer, decision port, owner lease or positive grant must fail closed.

**Policy contradiction:** the pre-existing Backend V2 action vocabulary for Terminal, SVC, Infrastructure and Reverse is broader than a read-only permission. These optional stages do NOT establish that terminal.execute or analysis.import are safe read grants. Runtime has not minted new Cedar action names. Backend must agree narrower read-only actions and resource scope before any product activation. Staging source does not make broad Permit acceptable.

Web adapter source was supplied in [draft PR #545](https://github.com/KobaProduction/briareus/pull/545) and imported into a separate Runtime branch for review. It and the Files owner factory remain optional. None of the ordinary deployed Hand servers calls any protected factory. There are no new ENV flags or provider credential copies.

## Validation and delivery gates

Native fixtures use ephemeral RSA-signed resource tokens, foreign-audience denials, missing owner/peer checks, fake Cedar Allow, owner-canonical argument rewriting and bounded metadata validation. Fixture responses are not real Rauthy/Cedar or Project acceptance. The complete original six Hand diagnostic-only smoke must remain true.

Backend handoff: one authenticated Project-to-resource owner protocol, narrow read-only Cedar actions, genuine Rauthy resource audiences. Deployment handoff: isolated browser worker, Files root preservation and exact authenticated private peer/Dev scopes. Runtime product acceptance: real signed User → Project → AgentSession → Cedar Permit → owner read → revoke → deny for Files first, then separate risk gates for all other Hands. A legacy read annotation does not authorize a tool.
