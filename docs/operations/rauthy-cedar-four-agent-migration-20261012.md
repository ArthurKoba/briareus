## Target service boundaries

Rauthy (Rust upstream) owns Human/Service users, OAuth2/OIDC, SSO/MFA, password, sessions, tokens/JWKS, identity groups and coarse IAM. Briareus never duplicates password/JWT signing or its own OAuth authorization-code flow. Briareus Platform Control still owns Teams, Projects and membership, independent of Rauthy Groups. Existing Briareus Authorization Python service retains AgentSessions, durable grants, approval workflow, policy versions, revocation and Cedar PARC evaluation (principal/action/resource/context). Cedar is embedded policy evaluator via pinned binding, NOT a mandatory standalone service or an accounts DB. The Control Panel API is an independent thin BFF to Rauthy Admin API and Platform/Authorization/Resources; Control Panel UI independently consumes same-origin API/OIDC code+PKCE. Gateway remains business-free route/stream/telemetry; Hands verify OAuth audiences and source-authorized AgentSession/Cedar decisions at their actual execution boundary.

Human OAuth session, Briareus AgentSession and Hand execution session are distinct lifecycles. Gateway is not a JTI, User or Cedar decision service. Preserve existing shared PostgreSQL server and owner databases/volumes. Rauthy requires a verified supported isolated schema/DB namespace and upstream-owned migrations — do not assume it can use the old Identity tables, create another physical server or silently repurpose its storage. Valkey only accelerator, not durable revocation truth.
